# 课程 4 · Python 记得上一轮，为什么模型未必知道？

课程 3 已经练过 messages、响应正文和 JSON。本课把它们接到真实模型上：先询问虚构的「星港观测站开放夜」，再问“那再带上我 8 岁的弟弟呢？”比较只发追问、带上历史两种请求。

**活动材料由人编写；课堂回答来自你实际调用的模型。课件没有预填模型输出，也没有人工回答模式。** 没带历史时，模型可能追问、猜测或碰巧答中；本课记录实际行为，不预设它必然答错。

打开 [lesson.ipynb](lesson.ipynb)，选择你已有的 **llm-from-zero** 内核。第一格打印实际 Python 路径，内核不必叫 `.venv`。从项目根目录或本课程目录启动均可。网络连接正常时，主实验约 30 分钟；可分成“接通并完成前两次请求”“构造历史、核对与算费”两段。

## 本课完成什么

1. 首次发送规则和问题，拿到真实回答。
2. Python 仍保存首次回答，但第二次请求只发送追问，观察模型会怎样处理缺少的信息。
3. 自己构造包含先前消息的列表，发送同一个追问，核对依据和结果。
4. 分别计算三次实验费用、两轮对话任务费用，用“结论 → 机制 → 实验记录 → 限制”解释结果。

课堂有 **2 处关键代码 TODO**。作业是 1 易、2 中、1 开放思考，共 100 分；需要独立写历史构造函数、3 条断言和费用函数。作业复用课堂结果，**不要求额外付费调用**。

## 选择服务并明确开始

配置格默认 `RUN_LIVE = False`，运行会停下，不会读取密钥或产生回答。准备好后把它改为 `True`，选择已有服务。随后每执行一个调用格，就可能产生一次费用；没有自动重试。默认路径共有 3 次真实调用。

```python
RUN_LIVE = True
PROVIDER = "deepseek"  # 或 "tokenhub"
MODEL = None
config = configure(provider=PROVIDER, model=MODEL)
```

`configure()` 只生成配置，不发请求。没有环境变量时，通过隐藏输入框读取密钥，仅保留在当前内核内存中；不会写入文件，配置的显示结果也不包含密钥。若环境不能隐藏输入，会停止，避免明文回显。不要将密钥写进代码、输出或作业。

| 服务 | 模型选择 | 环境变量 |
|---|---|---|
| DeepSeek | 默认 `deepseek-flash`；可在 `MODEL` 指定账号可用的模型 | `DEEPSEEK_API_KEY`；可选 `DEEPSEEK_MODEL` |
| 腾讯云 TokenHub | 在 `MODEL` 填控制台已开通的 **DeepSeek 系列**模型 ID；未填时会提示输入模型 ID | `TOKENHUB_API_KEY`；可选 `TOKENHUB_MODEL` |

TokenHub 对应按量 API，不对应 Token Plan 编程套餐。默认广州入口；新加坡账号可先设置 `os.environ["TOKENHUB_REGION"] = "singapore"`，密钥地域需要一致。不要仅凭模型名称相似，假设不同服务的权限和价格相同。

隐藏输入最直接。若使用环境变量，已经打开的 VS Code 子终端里设置变量，不会改变现有内核。需要让启动 Jupyter 的进程继承变量，例如从已设置变量的终端运行 `uv run --with jupyterlab jupyter lab`，再选择项目内核。本课请求代码只使用 Python 标准库，不需要模型 SDK。

## 请求设置及边界

接口资料于 **2026-10-31** 核实。请求采用 `thinking={"type": "disabled"}`、`temperature=0`、`max_tokens=2048`，非流式，等待上限 45 秒。这些设置用于控制课堂实验，**不承诺每次输出严格相同**。输出 token 上限也不是总费用预算。

本课使用普通 Chat Completions 请求，没有传服务端会话 ID。模型在这条接口中处理的是本次提交的消息；Python 里的变量不会自动加入请求。这不代表所有厂商、所有有状态会话产品都没有服务端历史管理。

程序只记录当前实验必要的回答、模型名、消息条数、用量和耗时，不把密钥写入文件。保存 notebook 时，已显示的回答和用量会随输出保存；提交前可清除输出。重启内核后，内存中的回答和配置需要重新准备，重跑调用格会再次请求。

## 费用怎样理解

课堂和作业统一使用**教学假设价**：输入 3 元 / 百万 tokens、输出 9 元 / 百万 tokens。这不是任一服务的真实报价。

- **两轮对话任务**：首次带规则提问 + 带历史追问，共 2 次请求。
- **三次课堂实验**：上述 2 次，再加一次不带历史的对照请求。
- 后续请求的 `prompt_tokens` 已经包括本次提交的历史，不要在它之外再次加算历史 token。
- 缺少 `usage` 时显示“无法核算”，不能把缺失记为 0。

费用函数统计传入的成功结果。重跑、超时、截断、过滤或其他失败请求不一定被这张表完整记录，**失败也可能计费**。缓存命中可能采用不同单价；实际费用应结合服务商当时价格、缓存规则和控制台账单核对。

## 遇到问题

| 现象 | 先检查什么 |
|---|---|
| `RUN_LIVE` 提示停止 | 明确选择服务、准备好调用后，修改配置格为 `True` |
| `NameError` | 是否先运行定义变量的上方单元；重启过内核后变量会消失 |
| 401 / 403 | 密钥所属服务、地域和模型权限 |
| 400 / 404 | 模型 ID、接口地址和所选模型支持的参数 |
| 额度不足 / 限流 | 服务商控制台，再决定是否手动重试 |
| 超时 / 连接失败 | 网络和服务状态；超时不等于服务端未处理或未计费 |
| 回答截断 / 被过滤 / 正文为空 | 当前结果未正常完成；先检查任务与输出要求，再决定是否重新请求 |
