## 课程依据与安排

完整的能力分析、逐课问题、实验、难度调整和预算在 [COURSE_PLAN.md](COURSE_PLAN.md)。设计依据是当前 homework 的代码、答案和输出，以及历史批改；不会仅按工作年限判断能力。

- 代码与实验：已经能完成有限差分验证、训练循环与对照实验，后续逐步增加完整小函数。
- 解释与估算：重点练习因果关系、条件变化、单位和漏算项；当前内存表已算对，不要求重复机械计算。
- 未答内容：只记作未验证，以小题补测，不阻塞全部新课。
- 每课按“预测 → 实验 → 解释 → 改变条件”学习，最后加一个短估算和面试追问。

| 课程 | 主线 | 完成后能说明什么 |
|---|---|---|
| 0–3 | 已学张量、自动求导、MLP、bigram、消息与 JSON | 保留现有成果，薄弱概念随新课补测 |
| **4–8** | 真实 API、token/embedding、attention、Transformer、推理与缓存 | 从文字输入到逐步生成的主要过程，为什么历史和用量会变化 |
| **9–11** | 结构化输出、HTTP/流式服务、容器与首次上云 | 请求经过哪些组件，结果怎样被使用，服务怎样复现 |
| **12–15** | 文件与数据库、向量检索、RAG、检索与回答评测 | 为什么答错、该改哪个环节、资料权限怎样落实 |
| **16–20** | 工具、工作流、Agent、上下文与 MCP | 谁执行动作、状态如何保存、何时停止、失败如何处理 |
| **21–24** | 云网络、权限、缓存/队列、排错恢复、效果性能费用 | 怎样定位故障、测量优化、说明架构与资源取舍 |
| **25–28** | 本地模型、微调判断、系统设计与模拟面试 | 哪些方法适合什么约束，能用项目记录回答追问 |

课程 4、5 已提供课件；6–28 是已设计的后续教学单元，按最新反馈和作业逐课制作。第 5 课增加完整函数、条件变化与资源估算，提供两段必做和选做挑战。大主题分 A/B 短实验，学习时间以掌握情况为准，不把“刷完 28 课”当成达到岗位要求。

## 怎么练

每课保留少量关键 TODO，新语法和无关辅助代码直接说明。随着掌握程度提高，从补步骤过渡到完成小功能、排查问题和自主取舍。旧作业不替用户重写，未提交的不提前给答案。

作业沿用 1 道简单、2 道中等、1 道困难思考，共 100 分。题目只考已教内容；解释和计算均预留逐项答案区，减少漏答。每次批改单独记录代码、解释、估算与迁移能力。
