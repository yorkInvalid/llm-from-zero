# 第 01 课 一次模型请求 怎样才算成功

打开 [lesson.ipynb](lesson.ipynb)，用已有 `llm-from-zero` 内核。可以从项目根目录、新路线目录或本课目录运行。只使用已有 Jupyter 依赖和 Python 标准库。

本课从两次真实模型请求，学会区分：请求是否返回、生成是否完成、答案是否有依据。然后练习诊断一组明确标注的人工故障记录，写一个结果完整性判断函数，并核算教学费用。

大约三段，每段 20–30 分钟；前段接通过 API 可快速完成。没有数学推导，不另设 homework。

## 调用约定

- `RUN_LIVE=False` 是初始状态。此时整本可浏览和运行准备部分，不会读取密钥或发请求；也不会用人工答案顶替真实模型结果。
- 准备调用时改为 `True`，选择 DeepSeek 或 TokenHub。配置只读取密钥，实际调用在后面的两个单元。
- DeepSeek 默认模型为 `deepseek-flash`。TokenHub 在 `MODEL` 填已开通的 DeepSeek 系列模型 ID，`REGION` 选择密钥所属的广州或新加坡站点。本课不适配其他系列的思考开关。
- 密钥读取 `DEEPSEEK_API_KEY` / `TOKENHUB_API_KEY`，没有则隐藏输入；不写进文件或 Notebook。已开 VS Code 子终端中临时设置的环境变量不会自动进入已有内核，隐藏输入最直接。
- 主实验两次真实请求，关闭思考，非流式，每次输出上限 512 tokens。重跑单元会再请求，不自动重试。网络操作等待参数 30 秒并非严格总耗时上限；超时也可能已计费。
- 输出保存后会留在 Notebook，提交或分享前可清除。没有后台调用、云资源创建或自动上传。

接口于 2026-11-03 核对：[DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[TokenHub](https://cloud.tencent.com/document/product/1823/132248)。可用模型和权限以账号为准。

## 文件

- `api_lab.py`：配置、请求、观察卡与教学费用计算。辅助代码已提供，课堂聚焦发送内容和如何解释响应。
- `data/device-loan.md`：人工编写的规则。回答来自真实模型，事实核对以这份规则为准。
- 课堂故障记录明确标为 `teaching_fixture`，仅用于练习诊断，不能证明账号曾经限流或发生故障。

## 交付检查的边界

课件验证使用临时通信替身，检查请求构造、成功和失败记录、缺失用量以及 Notebook 执行；没有替你调用付费模型。真实连通、模型回答与账号可用性，仍需在本课操作中验证。
