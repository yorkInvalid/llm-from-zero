# 第四课 · 回答错了，应该改哪里？

上节课你已经得到一次真实 DeepSeek 回答：输入 394 token、输出 80 token，引用了两个检索片段。也发现了两件事：一次能回答不等于所有问题都能回答；答案有引用也可能复述资料中的错误。

你随后问：“已经回答对了，为什么还要切小一点？”这一课从这个问题继续。**先明确哪里没达到要求，再决定是否修改。原来已经够用的部分，不为优化而优化。**

本课继续参考 Datawhale 第五章《系统评估与优化》，来源与改编范围见 [SOURCES.md](SOURCES.md)。不增加云资源、不换模型、不重新学习部署。没有 homework。

## 我们手里有什么，要得到什么

已有：第三课的三份公开中文资料、真实 BGE 模型缓存、Chroma、能调用的 DeepSeek/TokenHub。已有代码与记录全部保留。

这次要给“提示词学习资料助手”做一个小检查：对于八个明确问题，找回的材料够不够？如果不够，增加候选片段有没有帮助？如果材料给齐了，模型能否正确利用？

最终留下：一份问题集、两份检索报告、一次有理由的取舍、少量真实回答观察。默认不调用付费模型，终端只打印摘要；原文与消息在报告里按需展开。

```text
先确认原资料有没有答案
       │
       ├─ 没有 → 看是否明确说明资料不足，不用增加 k 硬凑
       │
       └─ 有 → 检索片段有没有找齐必要依据？
                         │
                         ├─ 没找齐 → 检查检索和问题表达
                         │
                         └─ 找齐 → 检查回答如何使用这些文字

另一个独立问题：原资料本身是否可靠？有依据不等于事实正确。
```

建议分三段，每段约 25–35 分钟：A/B 建立评价标准；C/D 比较一个改动；E/F 诊断回答并说明结论。不要一次阅读全部源代码。

## A · 怎样才算成功？先看八个问题

在 VS Code 打开本课文件夹。终端执行：

```bash
cd '/Users/yorkchen/文稿 - 陈尧的MacBook Pro/VibeCoding/llm-from-zero/cloud-ai-interview/04-rag-evaluation'
```

先打开 `cases.json`，不用运行模型。它是我们的小问题集：

| 编号 | 代表的情况 | 检查重点 |
|---|---|---|
| q01 | 分隔符有什么用 | 保留上节课已成功的例子，同时留意资料中的过强表述 |
| q02 | 回答怎样方便 Python 读取 | 换一种说法，能否找到结构化输出的说明 |
| q03 | 营销文案太长 | 能否找到具体修改方法 |
| q04 | 只要物流信息，还要方便程序读取 | 是否同时找到两处不同的依据 |
| q05 | 原文没有步骤 | 能否找到条件不满足时的处理规则 |
| q06 | 两类部门各关注什么 | 是否完整覆盖比较双方 |
| q07、q08 | 手机号、公司报销额度 | 资料没有答案，应该说明不足 |

每题的 `evidence` 是教师在原文中人工选定的必要依据，不是模型自己评自己；`expected` 是人工核对提示，**不会发送给回答模型**。你可以不同意标注，但要先打开原文说明原因，修订问题集后重跑两组实验。

例如 q04 要回答两件事：怎样只提取某方面的信息，以及怎样要求便于程序读取的格式。只找到了第一处，就不叫“依据已找齐”。

先定义一个非常有限、但可复查的指标：

> 标注依据找齐比例 = 找齐该题所有标注依据的题数 ÷ 资料有答案的题数。

本课有 6 道有答案题、2 道无答案题。假设找齐 5 道，就记 5/6，而不是 5/8。它**不是回答正确率，也不是完整专业评测体系**：只反映这组人工标注的依据是否被覆盖。等价解释可能在其他地方，需要人工复查，不能把自动标注失败直接当作检索绝对错误。

无答案题单独检查拒答，不能因为“找不到不存在的依据”给检索扣分，也不能因为返回三段文字就给它加分。

## B · 固定资料，运行第一份检查

```bash
./run.sh prepare --name study
./run.sh evaluate --index study --k 3 --name k3
open artifacts/runs/k3.html
```

`open` 是 macOS 用默认程序打开文件的命令，不启动新的 HTTP 服务。也可以在 Finder 中双击该 HTML 文件。报告在本机读取，不会自动上传结果。

这里 `run.sh` 只是为了缩短命令：它使用第三课的锁定 uv 环境来运行本课 `lab.py`，不是新增一种框架，也不要求选择 Jupyter 内核。

`prepare` 把第三课那三份原文复制成**本课的固定快照**，并建立本课独立索引。它复用 BGE 缓存，不重新下载另一套模型，不覆盖第三课的库或笔记。`study` 已存在时不会覆盖，想从头做可换名字。

`evaluate` 把八个问题逐一交给真实 BGE/Chroma，**不调用 DeepSeek**。`k=3` 表示每题取回三个候选片段，切分仍固定为 300 字符、40 目标重叠。

打开报告后，只先看上面的表：

- 哪些题“标注依据已齐”？
- 哪些题“标注依据未齐”？
- 无答案题是否单独显示？

点开某一道没找齐的题，依次展开“人工标注”与“本次检索片段”。亲眼看缺的是哪一处，不急着改代码。

如果本次全部找齐，就记录当前范围内没有发现检索缺失，不强造失败；仍可检查无答案和资料质量。制作时的教师结果放在 [VALIDATION.md](VALIDATION.md)，不是必须复现的标准分数。

<details><summary>自动检查究竟在检查什么？</summary>

本课先在固定原文里找到每段人工依据的字符范围，再检查检索片段是否覆盖这个范围。两个相邻片段合起来覆盖也算覆盖；只命中一个关键词不算。

你只需要看 `core.py` 的 `score_evidence()` 和 `summary()`。向量查询和 HTML 拼接已经提供，不必递归阅读依赖库。

```python
flags = [span_covered(span, hits) for span in spans]
```

这里为每处依据得到一个布尔值；两处依据 `[True, False]` 只覆盖一处，不叫找齐。`all(flags)` 要全部为 True。本课对没有依据的题单独返回 None，避免 `all([])` 在 Python 中为 True 而把无答案题误算成成功。
</details>

## C · 失败发生在哪一层？

先不要谈“换一个更强的大模型”。对没找齐的那一题，用这三句话判断：

1. 原文里有没有需要的信息？用人工标注回到原文检查。
2. 本次检索有没有把这些信息带回来？展开 hits 看文字，不只看文件名。
3. 信息给齐后，回答是否正确？这一点还没测，因为目前没调用生成模型。

假设模型最后凭训练知识答对了，但必要资料没有找回来，能说明检索成功吗？不能。这也说明“最终答对”和“按指定资料可靠回答”不是同一个检查目标。

同样，q01 的引用可能准确指向一句过强的原文。这个问题应当检查和修订资料，而不是靠增大 k 把错误变正确。本课保留原资料供追溯，不偷偷替换事实。

## D · 只改变 k，看看有无收益

先在 [NOTES.md](NOTES.md) 写一句你要尝试的理由，例如：“缺少第二方面的依据，猜测它排在前三名之外，试试前五名。”这只是待验证的猜测。

```bash
./run.sh evaluate --index study --k 5 --name k5
./run.sh compare k3 k5 --name k3-vs-k5
open artifacts/comparisons/k3-vs-k5.html
```

这次没有改切分、模型、资料或问题，只改返回数量。程序会检查两份记录的资料与问题集是否一致，防止把多个变化归因给 k。

看三件事：

- 哪道原先失败的题，现在依据找齐了？
- 原先成功的题有没有退步？不凭“多取两段应当不会变差”跳过检查。
- 每个问题的上下文增加了多少字符？平均值是不是掩盖了某一题的大变化？

**如果没改善，就可以决定不保留 k=5。** 这也是有效的实验结论。返回更多片段不保证补上真正缺失的内容，而且可能带来冗余。

字符数只用来观察输入体积，不能直接等同 token 或账单。数据库查询耗时也只是单次查询记录，不包括 embedding 加载、网络和生成，不称作整体延迟或 p95。

不要不断扩大 k 直到凑出漂亮结果。可以先做下一段的诊断，后续再按原因选择改写问题、拆分多意图问题、混合检索或重排。我们不会在这一课一次引入所有方法。

## E · 人工把依据给齐，检查回答端

这一段从“只看检索”进入“看真实回答”。先选一题，例如 q04。首先预览原检索结果将怎样发给模型：

```bash
./run.sh answer --run k3 --case q04
```

它会输出新 HTML 报告的位置。先打开报告，展开消息核对；没有 `--live` 就不会调用回答 API。

确认后，调用一次：

```bash
./run.sh answer --run k3 --case q04 --live
```

报告先展示答案，再折叠资料和完整消息，避免像第三课一样一上来打印大段 JSON。记录从第二课 `.env` 读取模型配置；根据你上次的超时，默认读取等待 60 秒、整体等待 90 秒。终端中已经设置的同名变量优先；没有修改旧课 `.env`。

接着做一次诊断对照：**人工选定两处确实包含依据的原文交给同一个模型**，保持原问题和回答规则不变。

```bash
./run.sh answer --run k3 --case q04 --evidence manual
```

先看消息：这里放的是实际原文附近的片段，不是 `expected` 中老师写好的答案。它明确标为人工选择，不伪装成自动检索成功。再执行：

```bash
./run.sh answer --run k3 --case q04 --evidence manual --live
```

对照两次真实回答，按下面的方式理解，别强行套结论：

| 观察 | 可以支持的判断 | 还不能说明什么 |
|---|---|---|
| 原检索缺依据且回答不完整；人工给齐后完整 | 当前证据选择值得优先排查 | 不能证明所有错误都来自检索，也不能靠一次随机生成排除其他原因 |
| 两次都答对 | 模型可能用已有知识或不完整材料补足 | 自动检索不因此变成成功 |
| 人工给齐后仍答错 | 进一步检查提示、资料表述、模型能力和输出要求 | 不能只继续扩大 k |
| 任一次超时 | 这次通信没正常完成 | 不直接计为答案错误，也不认定未计费 |

人工证据对照是诊断工具，不是部署方案；在线用户不会替我们选择答案原文。要自动化找到两类依据，下一步才考虑相应的检索改法。

本段最多先用两次真实调用。还想检查无答案行为时，可以选做一次：

```bash
./run.sh answer --run k3 --case q08 --live
```

核对是否明确说明资料没有报销额度。不能把“没有未知引用编号”当作正确拒答，仍需要读答案。

## F · 最后做一次取舍，形成面试表达

这次结论不预设为“效果提高了”。你可以真实地说：

> 我先用一组问题定位缺失，再只改变返回片段数量。比较依据覆盖与输入体积后，决定保留原配置或继续有针对性地排查。

请补上你实际的题目、数字和证据，不背上面这句话。

用 60–90 秒回答：“怎样判断 RAG 该改检索还是改回答？怎样证明一次改动有用？”至少解释：

- 先核对原资料，区分无答案和未检索到。
- 单独检查检索与生成，不能用最终答对反推检索必然正确。
- 固定问题和资料，一次改一个条件，回看原本成功的题。
- 人工依据对照能帮忙定位，但不保证因果，也不代表生产检索能力。
- 当前仅八道人工开发问题，没有独立测试集，不声称生产准确率。

一个短估算：假设第一轮对八题都生成回答，改动后又对八题生成，共多少次回答 API 请求？如果只对一题做自动证据与人工证据两次对照，又是多少？检索运行会不会调用回答 API？

<details><summary>核对</summary>

两轮各八题是 16 次。单题两种证据对照是 2 次。纯 evaluate 只运行本机 embedding/检索，不调用回答 API；本机资源仍有消耗。生成超时后的重试是新请求，实际费用以服务商记录为准。不要用一次输入 394 token 的记录估算所有问题的输入都一样。
</details>

## 运行边界

- 课程使用本课固定资料快照。修改第三课原文件，不会悄悄改变本课实验；需要新资料时新建索引。
- 返回片段可能包含来源文字的错误或不相关代码；打开原文判断，不执行其中的代码。
- 同名输出禁止覆盖；重复实验换 `--name`，回答记录自动生成新名字。
- `manual` 只有人工标注有依据的问题能使用；无答案题没有可补给的依据。
- 本课在 Mac 本机完成，无需启动 Uvicorn。`run.sh` 运行结束就退出，HTML 报告仍可打开。
- 教师验证在 `teacher-*` 中，与你的 `study/k3/k5` 分开；不自动填写你的学习记录。
