目标：能够把一个 AI 应用接通、部署、测量、排错，并解释自己的技术选择。学习重点是通用能力：云服务器、网络、API、数据与 RAG、工具调用、可靠性和成本。模型机制按实际问题补充，主课不要求数学推导。

## 我们手里有什么，要做什么

你已有 Python、后端和部分云操作经验，学过 token、embedding、attention，并自报通过李宏毅视频与笔记理解了 attention 和位置编码。沿用这些基础，直接进入应用实验。

前两课给一个虚构的小团队做“资料与事务助手”；第三课切换为可核对公开原文的“提示词学习资料助手”，服务与模型通信能力继续复用。此前主线：起点是一份设备借用说明和一个问题，之后再加入更多文件、不同访问权限和一个工单接口。业务材料是教学数据；模型回答、检索、数据库写入和部署由实际程序完成。还没做的部分不会算作项目经历。

这条链会逐步长出来：

```text
提问的人 → 我们的 HTTP 服务 → 找到有权限看的资料 → 模型 API → 带依据的回答
                    │
                    ├→ 工单数据库：查状态、保存草稿
                    └→ 请求记录：耗时、错误、用量、版本

本机先跑通 → 部署到一台 CPU 云服务器 → 再讨论扩容、恢复和替代方案
```

云服务器运行我们的程序；调用外部模型 API 时，模型运行在服务商那边。前期不租 GPU。

## 每次怎样学

每段只解决一个完整问题：先看到现象，再操作，沿同一条数据流解释，最后改变一个条件。图示用来展示请求、资料或状态流，不用装饰替代解释。

每课留下三样东西：一个可运行结果、一份短观察记录、一段能应对追问的解释。保留必要的费用或容量计算，不推导 attention、梯度或向量公式。课堂中做小功能和排错，不另外增加 homework 文件。

反馈分开记录：**跑通了、能解释、换条件仍会处理**。这些不互相替代，教师检查课件也不计作你的学习成果。
