# 用本机内核跑网页练习

这一课要做成「题干、代码框、运行、输出、检查」都在同一页，做法是让页面把代码交给学生 Mac 上已经装好 **tokenizers 0.22.2** 和 **torch** 的那个 Python，而不是在浏览器里再启动一个 Python。2026 年 11 月 1 日核对过的 Pyodide **314.0.7** 自带 **357** 个包，锁文件里有 `tiktoken` 和 `numpy`，没有 `tokenizers`、`torch`、`transformers`；PyPI 上的 tokenizers 0.22.2 是 **24** 个原生轮子，官方 torch **2.15.0** 是 **28** 个文件，两边都没有 wasm 或纯 Python 轮子，浏览器里的安装器因此接不上这门课的环境。编辑器本身不执行代码。Judge0、Piston 那类隔离服务是给网上陌生人交程序用的，要 Docker 和另一套运行时，一个人在自己电脑上学习用不上，也打不开本机那份约 **11 MB** 的 `tokenizer.json`。适合的做法是：讲义页自己画编辑框和运行按钮，背后用仍在发布的 **Jupyter Server 2.21.1**（2026-09-15）从课程的 uv 环境拉起一个真实内核，只听 `127.0.0.1`，学生打开的是讲义页。不需要租服务器，也不需要打开 JupyterLab。

## 浏览器里的 Python 装不上这两个库

Pyodide 是嵌在页面里的 CPython，用 WebAssembly 跑，页面作者自己写运行按钮，再调用 `runPython` 或 `runPythonAsync`；标准输出可以在启动时换掉，所以打印结果能出现在按钮旁边。JupyterLite 是整份在浏览器里的 Jupyter，Python 内核跑在 Web Worker 里，文档写明的嵌入方式是一个 REPL 的 iframe，学生可以不打开 JupyterLab 那套界面。当前稳定内核线是 `jupyterlite-pyodide-kernel` **0.8.*** 对上 Pyodide **314.*** 和 Python **3.14.***；JupyterLite 本体在 2026-10-30 发布了 **v0.8.7**。两条产品最后都落到同一个解释器上。这个解释器第一次拉起，核心文件大约 **6,237,877** 字节（`pyodide.asm.wasm` 3,438,516 字节，标准库压缩包 2,505,313 字节，再加上三份小文件）；文档里的「200 多 MB」是带上全部轮子的压缩包，不是打开页面时的那一次下载（[Downloading and deploying](https://pyodide.org/en/stable/usage/downloading-and-deploying.html)，[pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json)）。

装包的规则把这门课挡在外面。micropip 只接受纯 Python 轮子和按 Pyodide / Emscripten 编出来的轮子；带 C、Fortran 或 Rust 扩展、又没有纯 Python 轮子时，安装失败，报错是 `ValueError: Can't find a pure Python 3 wheel`。`file:` 形式的轮子地址在浏览器里不能用（[micropip basic usage](https://micropip.pyodide.org/en/stable/project/usage.html)，[FAQ](https://pyodide.org/en/stable/usage/faq.html)）。tokenizers 0.22.2 的文件名里没有 `wasm`、`emscripten`、`pyodide` 或 `none-any`；Mac arm64 那个轮子 **2,981,472** 字节，标签是 `cp39-abi3`，那是这台 Mac 上的 CPython 用的，不是浏览器里的 `wasm32`。0.22.0 和 0.22.1 同样只有原生轮子。PyPI 上更新的 tokenizers 是 0.23.3，也不改变 0.22.2 这份文件列表（[tokenizers 0.22.2](https://pypi.org/pypi/tokenizers/0.22.2/json)）。官方 torch 2.15.0 的 28 个文件同样没有 wasm 轮子（[torch](https://pypi.org/pypi/torch/json)）。因此 `await micropip.install("tokenizers==0.22.2")` 会撞上纯 Python 轮子检查。这个失败是从文件列表和安装规则推出来的：2026-11-01 没有在浏览器里实际跑出那段报错。

名字相近的替代品接不上这门课。锁文件里的 `tiktoken` 是 **0.12.0** 的 `pyemscripten_2026_0_wasm32` 轮子，包名是 TikToken，不是 Hugging Face 的 `tokenizers`，而且没有人核对过它能不能读 Hugging Face 的 `tokenizer.json`（[pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json)）。第三方的 `torch-pyodide` **0.0.84**（2026-06-07）是一个 **82,462** 字节的纯 Python 轮子，自述为 MVP：要先加载一份独立的 JavaScript / WebGPU 运行时，浏览器没有 WebGPU 适配器时 `torch.tensor` 会失败，文档示例钉的是 Pyodide **0.29.4**，覆盖面是张量运算和一部分 `torch.nn`，`torch.cuda.is_available()` 是空实现（[torch-pyodide](https://pypi.org/pypi/torch-pyodide/json)，[README](https://github.com/celsowm/torch-pyodide)）。那 82 KB 不是 GPU 运行时的体积，运行时有多大，读过的材料里没有写。即便有人为 Pyodide 314 手编一个 tokenizers 轮子，当前 FAQ 仍写明 `threading.Thread.start()` 会抛 `RuntimeError: can't start new thread`，fork 和 pthreads 不可用；tokenizers 自己的旧讨论里还有不开 `TOKENIZERS_PARALLELISM=0` 就会线程池 panic 的记录（[FAQ, threading](https://pyodide.org/en/stable/usage/faq.html)，[pyodide-recipes issue 199](https://github.com/pyodide/pyodide-recipes/issues/199)）。浏览器这条路的上限是：标准库练习可以在页面里跑，这门课要的两个库和它们的本地数据文件不行。

## 11 MB 的分词器进不了网页的任意路径

浏览器里的 Python 不能打开 `file:///.../tokenizer.json`。JavaScript 读 `file://` 会撞上同源策略。Pyodide 的默认文件系统是内存里的 MEMFS，刷新页面就没了；页面可以让学生用文件选择框读入字节，再 `FS.writeFile` 写进这块内存，原文件还在磁盘上，除非页面自己再把字节发出去，否则这一步不是上传。要让 Python 直接看见真实文件夹，得用 `showDirectoryPicker()` 之后的 `mountNativeFS`，文档里的权限示例要的是读写，而且写明这个文件系统接口「只在 Chromium 系浏览器：Chrome 和 Edge」里可用，日期注记是 2022-08-18；当前 FAQ 仍把 Firefox 和 Safari 排除在外（[FAQ, local files](https://pyodide.org/en/stable/usage/faq.html)，[Dealing with the file system](https://pyodide.org/en/stable/usage/file-system.html)）。这台 Mac 上若用 Safari，就只剩「每次把 11 MB 拷进标签页」这一条。JupyterLite 没有服务器，文件进的是浏览器的 IndexedDB 或 `localStorage`，同样是一份浏览器侧的副本，不是学生目录的实时挂载（[JupyterLite README](https://github.com/jupyterlite/jupyterlite/blob/main/README.md)）。

运行限制也是为公开网页设计的，不是为这一课设计的。WebAssembly 没有抢占式调度，主线程上的死循环会冻住页面；要能打断，得把 Pyodide 放进 Web Worker，再加 `SharedArrayBuffer` 和跨源隔离头，文档没有自动的墙钟超时（[Interrupting execution](https://pyodide.org/en/stable/usage/keyboard-interrupts.html)）。2020 年有维护者说过当时编译的 wasm 堆上限是 2 GB，当前 FAQ 没有重申这个数字，所以它不能当作 2026 年的规格（[Issue 1513](https://github.com/pyodide/pyodide/issues/1513)）。11 MB 的 JSON 在这份旧评论面前很小。挡住这一课的是轮子格式、本地文件必须由人点一次，以及线程不可用，不是文件体积。

## 竞赛沙箱隔离的是陌生人提交的代码

LeetCode 那种页面证明的是版面，不是运行时。它自己的帮助中心在 2022-11-17 写过：题目页上有编辑器，并感谢 CodeMirror；Run Code 针对当前测试用例跑，控制台展开后显示输入、你的输出和期望输出，编译错误也在同一块结果区；Submit 才送到「在线评测系统」，用一大组后台用例检查时间和空间（[Start your Coding Practice](https://support.leetcode.com/hc/en-us/articles/360012016874-Start-your-Coding-Practice)）。这篇文章没有写出队列、工人进程或超时是怎么实现的。一篇系统设计笔记直接说 LeetCode 几乎没有公开自己的评测机，于是把 isolate、Judge0、gVisor、Firecracker 当成「可以用来做评测机的已发表系统」来讨论，而不是当成 LeetCode 的架构事实（[Designing LeetCode](https://knowsys.tech/topics/74-design-leetcode)）。2024 到 2026 年的官方发布说明写的是编辑器偏好和竞赛回放，没有写评测进程。第三方扩展后来把页面上的编辑器描述成 Monaco，那是扩展作者的观察，不是 LeetCode 的声明。

编辑器库到 2026 年秋天都还在维护，而且都只改文字。Monaco Editor **0.57.0**（2026-09-24，MIT）用一次 `monaco.editor.create` 嵌进页面已有的节点，0.57.0 的语言表里有 `python`，那一项没有 worker，语言服务 worker 留给了 TypeScript、JSON、HTML 和 CSS（[monaco-editor](https://www.npmjs.com/package/monaco-editor)，[metadata.js](https://cdn.jsdelivr.net/npm/monaco-editor@0.57.0/esm/metadata.js)）。CodeMirror 6（npm 上的示例包 **6.0.2**，MIT）是一个 `EditorView`，`view.state.doc.toString()` 把缓冲读成字符串，Python 着色是另一个包 `@codemirror/lang-python` **6.2.1**（[Basic Editor](https://codemirror.net/examples/basic/)，[lang-python](https://www.npmjs.com/package/@codemirror/lang-python)）。Ace **1.45.2**（2026-10-21，BSD-3-Clause）仍可用脚本标签嵌进去。三个库都不启动解释器。运行按钮若要像那些产品一样工作，得把源码送到页面以外的一个进程，加上时间上限，再把 stdout、stderr 和判定画回同一页。

自建的公开评测机把这份隔离做成了一套要长期打补丁的服务。Judge0 是 GPL-3.0，默认编排是 API 服务器、worker、Postgres 16.2 和 Redis 7.2.4，服务器和 worker 都是 `privileged: true`，沙箱是 Isolate，依赖 Linux 的命名空间和 cgroup（[judge0](https://github.com/judge0/judge0/)，[docker-compose.yml](https://raw.githubusercontent.com/judge0/judge0/master/docker-compose.yml)，[compilers](https://github.com/judge0/compilers)）。它的返回值里已经有 Accepted、Wrong Answer、Time Limit Exceeded；`cpu_time_limit` 按分配到的 CPU 秒计，`wall_time_limit` 是墙钟秒，文档要求墙钟设得比 CPU 宽很多，用来对付 `sleep`。Piston 的仓库页标的是 MIT，执行接口收 `run_timeout` 和内存上限，返回 stdout、stderr、退出码和信号，没有 Accepted / Wrong Answer 字段；宿主要求 Docker、cgroup v2，并且关掉 cgroup v1。仓库文字写明公开 API 从 **2026-02-15** 起不再免费开放，个人项目不发密钥，要自己跑实例（[Piston](https://github.com/engineer-man/piston/)，[API v2](https://piston.readthedocs.io/en/latest/api-v2/)）。这两份材料都是按 Linux 宿主写的，没有一份写成「在 Docker Desktop for Mac 上给一个学生用」的步骤。CodeSignal 和 Replit 的第一方文章描述的是每人一个容器或正在铺开的 microVM，因为同一台机器上跑的是许多人的代码（[Replit, 2026-04-20](https://replit.com/blog/defense-in-depth-how-replit-secures-every-layer-of-the-vibe-coding-stack)）。

这一课的运行者就是这台 Mac 的主人。值得抄的是「编辑器是文本框，运行有时间上限，输出和判定回到同一页」。多租户的队列、特权 isolate、每人一个容器，解决的是陌生人。Python 自己的 `subprocess.run(..., capture_output=True, timeout=...)` 会在超时后杀掉子进程并抛 `TimeoutExpired`，非零退出可以变成 `CalledProcessError`，里面带着退出码和捕获的流；未处理异常的回溯会打出来（[subprocess](https://docs.python.org/3/library/subprocess.html)，[Errors and Exceptions](https://docs.python.org/3/tutorial/errors.html)）。这个超时管的是卡住的子进程，不提供单独的文件系统或单独的用户。它也不自动等于课程的 uv 环境：Judge0 和 Piston 安装的是它们自己的语言运行时。若指向 `.venv` 的解释器，一次短进程可以 `import tokenizers` 和 `import torch`，也可以用普通路径读那 11 MB 的文件。代价是每次点击都重新启动解释器，torch 和分词器都要再加载一遍，变量也留不住。笔记没有把「一个学生、一个 Docker 容器包住同一个虚拟环境」写成某个产品的用法，那只是从一般 Docker 用法推出来的，还要自己维护 Docker Desktop 和镜像。

## 真实内核留住变量，并直接打开磁盘上的文件

浏览器说不了 ZeroMQ。页面若要使用真正的 CPython，机器上得有一个进程把 HTTP 和 WebSocket 翻成内核协议。2026 年仍在发版、又能拉起已有 CPython 的是 Jupyter Server：PyPI 上的 **2.21.1** 于 2026-09-15 上传，内核用 ZeroMQ，网页用一条 WebSocket 把多个通道复用在一起，`POST /api/kernels` 启动，`POST /api/kernels/{kernel_id}/restart` 重启，`POST .../interrupt` 打断（[jupyter-server](https://pypi.org/project/jupyter-server/)，[REST API](https://jupyter-server.readthedocs.io/en/latest/developers/rest-api.html)，[WebSocket protocols](https://jupyter-server.readthedocs.io/en/latest/developers/websocket-protocols.html)）。`jupyter_client` **8.10.0**（2026-08-28）是这套协议的参考实现，`KernelManager` 用 `Popen` 在本机起一个子进程；它是服务器用的 Python 库，静态页面不能 import 它（[KernelManager](https://papyri.dev/project/jupyter_client/8.10.0/jupyter_client.manager$KernelManager/)）。Kernel Gateway 3.0.1 停在 2024-03-12，做的是同一件事的无头封装，之后没有上游版本。Jupyverse **0.14.18**（2026-10-23）是另一个仍在发布的 FastAPI 服务器；它被讨论过的 `POST .../execute` 要的是文档 id 和单元格下标，当时标成实验功能，不是「把任意字符串交给内核」的接口（[Jupyverse](https://jupyter-server.github.io/jupyverse/)，[JupyterLab issue 12867](https://github.com/jupyterlab/jupyterlab/issues/12867)）。

页面可以完全是讲义。Thebe 的普通包把静态 HTML 里带 `data-executable="true"` 的代码块变成它自己的编辑器，并放上运行和重启；一页只有一个内核，所以连续点击共享 import、变量和函数。重启是单元格上的按钮，也是 `ThebeSession.restart()`，底层走到 Jupyter 的重启路由。npm 上的 `thebe` 是 **0.9.3**，发布于 2025-01-28，仓库没有标成归档，但 2025 年 1 月之后没有更新的正式版本；文档里的本地示例仍写成 `jupyter notebook --NotebookApp.token=... --NotebookApp.allow_origin=...`（[Thebe](https://thebe.readthedocs.io/en/latest/)，[local server example](https://thebe.readthedocs.io/en/latest/_static/html_examples/local.html)，[thebe on npm](https://registry.npmjs.org/thebe)）。Jupyter Server 2.x 的配置对象是 `ServerApp` 和 `IdentityProvider`，`ServerApp.token` 在 2.0 已弃用，改为 `IdentityProvider.token`。照着 Thebe 那段旧命令逐字敲，不保证页面等到的来源和令牌就是服务器设下的那个。Thebe 适合当作现成的页面客户端；这一年还在收修复的是服务器。

内核没有自己的窗口。`ServerApp.open_browser` 默认是 false。学生要开着的是一条从 uv 环境启动的服务，然后在浏览器里打开讲义 HTML。能 `import torch` 和 `import tokenizers` 的条件是：这个服务的 Python 就是那个环境，或者 kernelspec 的解释器指回它，并且里面装了 `ipykernel`。笔记没有在这门课的虚拟环境里执行 `jupyter kernelspec list`，所以「ipykernel 已经装好」仍未核对。内核是单独进程，计算状态从一次执行留到下一次，重启才清空；会话 id 在重启后应换新，客户端看到新 id 就该当作内核已重启（[Running Code](https://jupyter-notebook.readthedocs.io/en/stable/examples/Notebook/Running%20Code.html)，[Messaging](https://jupyter-client.readthedocs.io/en/stable/messaging.html)）。状态在进程里。关掉浏览器标签，文档并没有说进程因此被清掉；服务器退出或内核进程结束，状态才没。讲义页得自己提供重启，因为屏幕上没有 JupyterLab 的 Kernel 菜单。

本机要处理的是端口、令牌和来源，不是沙箱。Jupyter Server 的令牌默认开启，凭据意味着可以跑任意代码；空令牌加空密码会关掉认证，文档不建议。Kernel Gateway 的 `auth_token` 默认是空字符串，那表示本机端口上的代码执行没有认证。讲义应使用固定令牌，绑定 `127.0.0.1`，不要用它 Docker 示例里的 `0.0.0.0`。`allow_origin` 默认是空。页面和服务器端口不同，就得把允许的来源设成讲义页的来源；Thebe 的示例是讲义在 `http://127.0.0.1:8080`，内核在 8888。CSRF 规则接受「本服务器发出的页面」或「带令牌的请求」，所以另一端口上的讲义在令牌送出时可以工作（[Security](https://jupyter-server.readthedocs.io/en/latest/operators/security.html)）。两个进程都想占 8888 时会撞车；Kernel Gateway 默认可以向上再试 50 个端口，页面若写死 8888，会连到一个已经悄悄挪走的服务。协议要求执行结果始终带 `text/plain`，所以 `print` 和表达式结果可以显示；前端可以忽略自己不懂的 MIME，只读纯文本的渲染器会丢掉 `image/png`。活动的滑块或 ipympl 需要 comm 通道和 widget 管理器，Thebe 的示例覆盖了这一点。练习里若有 `input()`，页面得回答 `input_request`，否则执行请求应设 `allow_stdin: false`。

磁盘上的分词器在这条路上就是普通文件。内核进程的当前目录和权限就是启动它的那个用户，Python 按路径 `open` 那 11 MB 的 `tokenizer.json`，不经过文件选择框，不拷进标签页，刷新讲义页也不会把文件从 MEMFS 里丢掉。这是「必须使用本机已有环境」落到文件上的直接结果。

## 这一课用本机服务，把判定画在同一页

三件事可以拆开选。版面选 LeetCode 帮助文章里的那一页：题干、编辑器、运行之后在同一页展开的输入、输出、期望输出和错误。编辑器选 CodeMirror 6 或 Monaco，只负责着色和把缓冲读成字符串；若希望少写客户端，Thebe 0.9.3 已经把代码块、运行、重启和输出做在一页里，代价是客户端停在 2025 年 1 月，启动命令要改写成 Jupyter Server 2.x 的 `IdentityProvider.token`（或环境变量 `JUPYTER_TOKEN`）、`ServerApp.allow_origin` 和 `--no-browser`。运行选从课程 uv 环境启动的 Jupyter Server 2.21.1，内核名用该环境里存在的 `python3`，只听本机，令牌写进讲义配置。检查是页面上的几行比较：对照 `text/plain`，或在同一个内核里跑一段检查函数再看退出状态。重启按钮清掉命名空间，下一次运行重新 `import`。

浏览器内运行留在「只需要标准库、可以接受另一套 Python」的练习。它省掉本机服务，第一次大约下载 6.2 MB 核心，然后在缺轮子的地方停住。编辑器加竞赛沙箱留在「代码来自不信任的人、宿主是 Linux」的系统。这一课两边都不是。一次一进程的 `subprocess` 可以指向同一个 `.venv`，超时也有文档，适合那种每次运行都必须从空白解释器开始的短检查；这一课要反复试分词和张量，内核把 import 和已经读入的分词器留在进程里，点击运行才像笔记本，同时学生看的仍是讲义页。

还没在这台机器上核对的有三件：uv 环境里是否已经有 `ipykernel` 以及 `kernelspec` 的显示名；2026 年的 CLI 是否按 `--IdentityProvider.token=` 和 `--ServerApp.allow_origin=` 这样的拼写生效；Thebe 0.9.3 对上 Jupyter Server 2.21.1 时，令牌和跨源是否只靠文档里的 `baseUrl` 加 `token` 就能通。前两件是开写页面前在本机跑一次启动命令就能确定的。第三件若不通，页面改为自己按 Jupyter 的 WebSocket 协议发 `execute_request`，服务器仍是同一个。

## Conclusion

LeetCode 看起来像一个产品，拆开是两层：一层是同一页上的编辑和结果，一层是为陌生人准备的隔离。这一课缺的是第一层。环境已经在学生的 Mac 上，分词器已经是一个本地文件，所以第二层会把可用的解释器换成一套装不上这两个库的运行时。

一旦运行发生在课程那个 Python 进程里，讲义和 Jupyter 之间的来回就消失了：学生打开的页面就是练习，内核没有窗口，11 MB 的文件按路径读取，上一次运行留下的名字下一次还在。剩下的设计风险是启动命令的拼写和令牌放在本机页面里，这是一个人、一个回环地址上的配置，不是一份要租来的服务器。
