## What are Pyodide and JupyterLite as of 2026, and how does a page embed them so the learner never opens JupyterLab?

### Takeaway

Both can run inside the page the student already has open. Pyodide is the Python runtime and has no editor; the page supplies the text box and the Run action. JupyterLite is a browser-only Jupyter distribution whose small REPL can be placed in an iframe so the student never opens the JupyterLab application.

### Cited Findings

- Pyodide is “a Python distribution for the browser and Node.js based on WebAssembly” and “a port of CPython to WebAssembly/Emscripten.” In the browser it can install packages with micropip. Pure-Python wheels on PyPI are supported, and many C, C++, and Rust extensions have been ported, including NumPy, pandas, SciPy, Matplotlib, and scikit-learn. It includes a JavaScript/Python foreign-function interface, async/await, and access to Web APIs. — [Pyodide stable home](https://pyodide.org/en/stable/)
- A page embeds Pyodide by loading `https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide.js` and calling `loadPyodide()`, then `pyodide.runPython(...)`. After startup, only the standard library is available until more packages are loaded. The same page documents a hosted REPL, which is a separate browser page, not an embedded editor. — [Getting started](https://pyodide.org/en/stable/usage/quickstart.html); [Using Pyodide](https://pyodide.org/en/stable/usage/index.html)
- `loadPyodide()` returns the Pyodide API. `stdout`, `stderr`, and `stdin` can be replaced at startup, which is how a page can show printed output next to a Run control. `runPython` evaluates code synchronously; `runPythonAsync` evaluates code that uses `await`. — [JavaScript API](https://pyodide.org/en/stable/usage/api/js-api.html); [FAQ, stdin/stdout and runPython](https://pyodide.org/en/stable/usage/faq.html)
- Stable docs tell browser users to use at least Firefox 112 (2023-04-11), Chrome 112 (2023-03-29), or Safari 16.4 (2023-03-27). From Pyodide 0.25.0, Node.js older than 18 is not officially supported. That Node note is about a backend JavaScript host, not the student browser. — [Using Pyodide](https://pyodide.org/en/stable/usage/index.html)
- The recommended CDN channel is `https://cdn.jsdelivr.net/pyodide/v314.0.7/full/`, described as cached by the browser. The dev channel is not cached and is for testing. The full GitHub tarball `pyodide-314.0.7.tar.bz2`, which vendors the wheels, is “quite large (200+ megabytes).” The smaller `pyodide-core-314.0.7.tar.bz2` is the set needed to start. Any static host that sets the WASM MIME type and CORS headers works, including GitHub Pages. Local serving is `python -m http.server` from the distribution folder. — [Downloading and deploying](https://pyodide.org/en/stable/usage/downloading-and-deploying.html)
- Measured on 2026-11-01 with HTTP 206 `Content-Range` against that CDN (these byte sizes are not written as a single total in the docs): `pyodide.asm.wasm` 3,438,516 bytes; `python_stdlib.zip` 2,505,313 bytes; `pyodide.asm.mjs` 262,041 bytes; `pyodide.mjs` 7,299 bytes; `pyodide-lock.json` 24,708 bytes. Sum of those five files: 6,237,877 bytes. HEAD responses for the same URLs returned status 200 and no `Content-Length`. — [pyodide.asm.wasm](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide.asm.wasm), [python_stdlib.zip](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/python_stdlib.zip), [pyodide.asm.mjs](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide.asm.mjs), [pyodide.mjs](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide.mjs), [pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json)
- JupyterLite “is a JupyterLab distribution that runs entirely in the browser” built from JupyterLab components. It has no dedicated application server. Python kernels run in a Web Worker. The Pyodide kernel is `jupyterlite-pyodide-kernel`; a second Python option is Xeus via `jupyterlite-xeus`. It can show the JupyterLab interface and the Notebook interface, and it is “embeddable within larger applications.” Notebook edits are saved in the browser’s IndexedDB or `localStorage` (the README spells IndexedDB as “IndexDB”). The README’s compatibility table on `main` stops at `jupyterlite-core` 0.7.0 and says only the last two releases are supported. That table is behind the GitHub release `v0.8.7` dated 2026-10-30. — [JupyterLite README](https://github.com/jupyterlite/jupyterlite/blob/main/README.md); [releases API](https://api.github.com/repos/jupyterlite/jupyterlite/releases?per_page=3)
- Stable kernel docs: `jupyterlite-pyodide-kernel` 0.8.* is the stable row matched to `jupyterlite-core` `>=0.8,<0.9`, JupyterLab `>=4.6.0,<4.7`, Pyodide `314.*`, Python `3.14.*`, Emscripten `5.0.3`. Kernel 0.7.* matches Pyodide `0.29.*` and Python `3.13.*`. The kernel “does not yet work in a full, `jupyter_server`-hosted client such as JupyterLab or Notebook.” `jupyter lite build` includes a kernel that uses the full Pyodide CDN distribution. The `latest` docs add an alpha row `0.9.*`. — [jupyterlite-pyodide-kernel stable](https://jupyterlite-pyodide-kernel.readthedocs.io/en/stable/); [latest](https://jupyterlite-pyodide-kernel.readthedocs.io/en/latest/)
- The kernel overview says the Pyodide kernel uses IPython, can install packages at runtime with `piplite` (example `await piplite.install("ipywidgets")`), supports `time.sleep`, and “Does not support pre-installing packages.” A later howto says packages in the Pyodide distribution can be imported directly, extra wheels can be shipped at build time, and packages outside the distribution use `await micropip.install` or `%pip install`. Those two stable pages disagree about preinstalling. — [Adding kernels](https://jupyterlite.readthedocs.io/en/stable/howto/configure/kernels.html); [Ship additional wheels](https://jupyterlite.readthedocs.io/en/stable/howto/pyodide/wheels.html)
- Default JupyterLite uses the CDN because “the full distribution is very large.” A custom `pyodideUrl` can point at another `pyodide.js`. — [Using a custom Pyodide distribution](https://jupyterlite.readthedocs.io/en/stable/howto/pyodide/pyodide.html)
- Embedding without the Lab UI is an iframe of the REPL app, which “is based on the JupyterLab Code Console,” not the full Lab workspace. Documented snippet: `https://jupyterlite.github.io/demo/repl/index.html`. URL parameters include `kernel=python` (skip the kernel picker), `toolbar=1`, `code=...`, `execute=0` (fill the prompt and do not run it), theme, `clearCellsOnExecute`, `hideCodeInput`, `promptCellPosition` (`top`/`bottom`/`left`/`right`), and `showBanner=0`. The docs show combining those into “a single executable cell.” The toolbar includes a “Copy Shareable Link” button. — [Embed a live REPL](https://jupyterlite.readthedocs.io/en/stable/quickstart/embed-repl.html)
- The public `try/lab` and `try/tree` links are the full JupyterLab and Notebook interfaces inside the browser. Using those would be opening JupyterLite’s JupyterLab UI. The REPL iframe is the documented way to avoid that UI. — [JupyterLite README](https://github.com/jupyterlite/jupyterlite/blob/main/README.md)

### Inferences

- A LeetCode-style Run button is not a Pyodide or JupyterLite product feature. With Pyodide, the page author writes the button and calls `runPython` or `runPythonAsync`. With JupyterLite, the student can stay inside an iframe REPL and never navigate to `/lab`.
- First load of Pyodide 314.0.7 is on the order of the 6,237,877-byte core set above, then more bytes for each extra package. The documented “200+ megabytes” figure is the full vendored tarball, not the initial page download.
- JupyterLite 0.8.7 (2026-10-30) plus kernel 0.8.x is the line that matches current Pyodide 314 / Python 3.14. Kernel 0.7.x is the older Pyodide 0.29 / Python 3.13 line.

## Can they install or use Hugging Face tokenizers 0.22.x and PyTorch?

### Takeaway

`tokenizers==0.22.2` and official PyTorch are not usable through current Pyodide or the JupyterLite Pyodide kernel. Micropip will only install a pure-Python wheel or a Pyodide/Emscripten wheel; PyPI’s tokenizers 0.22.x files are native wheels only, and the Pyodide 314.0.7 lock has neither `tokenizers` nor `torch`. A third-party package named `torch-pyodide` exists and is not official PyTorch.

### Cited Findings

- Micropip installs pure-Python wheels from PyPI, and Pyodide-built packages. For a package with C, Fortran, or Rust extensions and no pure-Python wheel, install fails with `ValueError: Can't find a pure Python 3 wheel`. The documented fix is a WASM/Emscripten wheel, either from the Pyodide distribution or from a URL / `emfs:` path. Version specifiers such as `package==1.2.3` are supported. In browsers, PyPI downloads are cached. The package index must support CORS. `file:` wheel URIs do not work in the browser. — [micropip basic usage](https://micropip.pyodide.org/en/stable/project/usage.html); [micropip API](https://micropip.pyodide.org/en/latest/project/api.html); [Loading packages](https://pyodide.org/en/stable/usage/loading-packages.html); [FAQ on pure-Python wheels](https://pyodide.org/en/stable/usage/faq.html)
- The Pyodide 314.0.7 lockfile has 357 packages. Names present that are easy to confuse with this lesson: `tiktoken` and `numpy`. Names absent: `tokenizers`, `torch`, `transformers`. Lock metadata: Python `3.14.2`, platform `emscripten_5_0_3`, arch `wasm32`, ABI `2026_0`. — [pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json)
- The stable “packages built in Pyodide” page is the same distribution list. A search excerpt of that page includes `cffi 2.0.0`, `numpy 2.4.6`, and `micropip 0.11.1`. An older claim that PyTorch could not be ported because CFFI was unsupported is therefore out of date; CFFI is in the current list, and `torch` still is not. — [Packages built in Pyodide](https://pyodide.org/en/stable/usage/packages-in-pyodide.html). Older claim: [Stack Overflow answer](https://stackoverflow.com/questions/64358372/run-pytorch-in-pyodide) (maintainer comment from the early Pyodide period; do not treat it as the 2026 blocker).
- PyPI `tokenizers` 0.22.2 has 24 files. None of the filenames contain `wasm`, `emscripten`, `pyodide`, or `none-any`. Tags include macOS (`macosx_11_0_arm64`, `macosx_10_12_x86_64`), manylinux, musllinux, and Windows, plus an sdist. The Mac arm64 wheel is 2,981,472 bytes and is still a native `cp39-abi3` wheel. 0.22.0 and 0.22.1 are the same kind of native-only set (15 files each, also no wasm/pure wheel). Latest tokenizers version on PyPI is 0.23.3. 0.22 versions listed: `0.22.0`, `0.22.0rc0`, `0.22.1`, `0.22.1rc0`, `0.22.2`, `0.22.2rc0`. — [tokenizers 0.22.2 JSON](https://pypi.org/pypi/tokenizers/0.22.2/json); [tokenizers project JSON](https://pypi.org/pypi/tokenizers/json)
- A Pyodide recipe request for `tokenizers` was still described as open in a search snippet, last updated 2025-07-21. That issue records a 2022 custom build and a demo, plus a thread-pool panic unless `TOKENIZERS_PARALLELISM=0`. A 2023 draft pull request to add `tokenizers` was closed and was not a merged package. Those snippets were not re-fetched as HTML on 2026-11-01, and they do not claim a 0.22.2 wheel for Pyodide 314. — [pyodide-recipes issue 199](https://github.com/pyodide/pyodide-recipes/issues/199); [pyodide PR 3422](https://github.com/pyodide/pyodide/pull/3422); [2022 demo](https://josephrocca.github.io/tokenizers-pyodide/demo/)
- Wheels built for Pyodide are named `*-cpXXX-cpXXX-pyodide_XXXX_X_wasm32.whl` and match one Pyodide/Emscripten generation. The build doc says PyPI does not currently accept emscripten/wasm32 wheels, citing PEP 783 for future plans. That sentence is from the 0.29.2 build page, so it may be older than the 314 line; the 0.22.2 PyPI file list above still has no such wheel. — [Building packages, Pyodide 0.29.2 docs](https://pyodide.org/en/0.29.2/development/building-packages-from-source.html)
- The 314.0.7 lock entry for `tiktoken` is version 0.12.0, file `tiktoken-0.12.0-cp314-cp314-pyemscripten_2026_0_wasm32.whl`, imports `tiktoken` and `tiktoken_ext`, and depends on `regex` and `requests`. The same filename appears on the 314.0.5 index next to ordinary macOS, Linux, and Windows wheels. This is TikToken, not Hugging Face `tokenizers`. Whether it can read a Hugging Face `tokenizer.json` was not checked. — [pyodide-lock.json](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json); [tiktoken on the 314.0.5 Pyodide index](https://index.pyodide.org/314.0.5/tiktoken/)
- PyPI `torch` 2.15.0, the latest release read on 2026-11-01, has 28 files. None of those filenames contain `wasm`, `emscripten`, `pyodide`, or `none-any`. — [torch project JSON](https://pypi.org/pypi/torch/json)
- PyPI project `torch-pyodide` latest is 0.0.84, summary “PyTorch-compatible module … via Pyodide + WebGPU,” uploaded 2026-06-07. The wheel is `torch_pyodide-0.0.84-py3-none-any.whl`, 82,462 bytes, plus an sdist of 86,319 bytes. — [torch-pyodide JSON](https://pypi.org/pypi/torch-pyodide/json)
- The project README calls itself an MVP. Browser use needs two parts: the Python wheel via micropip, and a JavaScript/WebGPU runtime loaded first (`installTorchRuntime`). The README example pins `pyodide/v0.29.4`, not 314.0.7. It says `torch.tensor(...)` fails if the browser has no WebGPU adapter. The manifest at `https://celsowm.github.io/torch-pyodide/latest.json` carries `runtimeUrl`, `wheelUrl`, and sha256 fields. The documented working surface is a subset: tensor creation, arithmetic, matmul, a list of unary ops, reductions, shape ops, indexing, and some `torch.nn` modules (`Linear`, `Conv2d`, normalization, dropout, pooling, losses, activations). `torch.cuda.is_available()` is a stub. — [torch-pyodide README](https://github.com/celsowm/torch-pyodide); [PyPI 0.0.75 page text in search](https://pypi.org/project/torch-pyodide/0.0.75/) (older than the 0.0.84 JSON above; treat the feature list as the project’s own description, not an audit)

### Inferences

- `await micropip.install("tokenizers==0.22.2")` on Pyodide 314.0.7 should fail the pure-Python-wheel check. The macOS arm64 wheel on PyPI is the native wheel for CPython on the student’s Mac, and it is the wrong platform for the browser’s wasm32 runtime.
- Official `import torch` from PyTorch is not available in this stack. `torch-pyodide` can be installed as a small pure-Python wheel, but only after its separate JS runtime, only with WebGPU, only for the subset it implements, and the published example was written against Pyodide 0.29.4. The 82 KB wheel is not the GPU runtime size; that runtime’s byte size was not documented in the sources read here.
- Shipping a hand-built tokenizers wheel would be a custom Pyodide package build pinned to one Emscripten version. That is outside “install the 0.22.2 PyPI release,” and no current official wheel was found.

### Gaps

- No runtime test was executed in a browser on 2026-11-01, so the install failure is inferred from the file list and micropip’s rules, not from an observed traceback on Pyodide 314.0.7.
- Whether TikToken 0.12.0 can read a Hugging Face `tokenizer.json` was not checked; it should not be treated as a substitute without that check.
- The WebGPU runtime byte size for `torch-pyodide`, and whether 0.0.84 actually imports on Pyodide 314 / Python 3.14, were not found in an official Pyodide or PyTorch document.
- The tokenizers recipe issue’s open/closed state after 2025-07-21 was not re-fetched.

## How does local file access work for a tokenizer file that must stay on the student’s machine?

### Takeaway

The browser will not let Python open an arbitrary path such as `file:///.../tokenizer.json`. The student has to pick the file or, in Chrome only, a folder. A normal file picker copies the 11 MB into the tab’s memory; the original stays on disk, and that copy is not a server upload unless the page sends it. Safari, per the current FAQ, cannot mount the real folder.

### Cited Findings

- JavaScript cannot load `file:///path/to/local/file.data`. Trying to do so hits the same-origin policy. The FAQ says a File System API exists “in Chrome but not in Firefox or Safari,” and points at Pyodide’s native-filesystem section. For development, files can be served by a web server instead. — [FAQ, local files](https://pyodide.org/en/stable/usage/faq.html)
- The default filesystem is Emscripten MEMFS, in memory, and “will be lost when the page is reloaded.” JavaScript writes with `pyodide.FS.writeFile(path, data)` and Python then reads that path with `pathlib`. Other mounts include `IDBFS` (IndexedDB in the browser; changes persist only after `FS.syncfs()`), `NODEFS` (Node.js only), `PROXYFS`, and `WORKERFS`. — [Dealing with the file system](https://pyodide.org/en/stable/usage/file-system.html); [FAQ, IndexedDB sync](https://pyodide.org/en/stable/usage/faq.html)
- `pyodide.mountNativeFS(path, directoryHandle)` mounts a directory the user picked with `showDirectoryPicker()`. The permission call in the docs asks for `readwrite`. The mount path must be empty or missing. Reads through the mounted path are visible to Python. Writes stay in the browser view until `syncfs()`; the docs say the new file “does not exist in native file system” before that call and does exist after it. The same page says this File System Access API “is only supported in Chromium based browsers: Chrome and Edge (as of 2022/08/18).” That date is inside the current stable page. — [Dealing with the file system](https://pyodide.org/en/stable/usage/file-system.html); [Accessing files quick reference](https://pyodide.org/en/stable/usage/accessing-files.html)
- The quick reference says the directory handle can be stored in IndexedDB so the folder picker is not shown every time, but the browser still prompts for read and write permission. Its sample asks for `mode: "readwrite"`. — [Accessing files quick reference](https://pyodide.org/en/stable/usage/accessing-files.html)
- An older API page (Pyodide 0.27.2) says a `FileSystemDirectoryHandle` can currently be acquired only in Chrome, including via `navigator.storage.getDirectory()` or `showDirectoryPicker()`. — [JavaScript API 0.27.2](https://pyodide.org/en/0.27.2/usage/api/js-api.html)
- JupyterLite has no server. The README says users “edit, save, and download from the browser’s IndexDB (or localStorage).” Putting a file into that environment stores a browser-side copy. — [JupyterLite README](https://github.com/jupyterlite/jupyterlite/blob/main/README.md)
- A Pyodide maintainer wrote in discussion 5458 that files in the Emscripten filesystem do not count toward the wasm heap limit; they “live outside wasm memory.” Another comment on that thread had said the opposite. The discussion is not a 2026 memory-limit specification. — [Discussion 5458](https://github.com/pyodide/pyodide/discussions/5458)

### Inferences

- For a Mac student, Chrome or Edge can mount the folder that contains `tokenizer.json` and let Python open `/mount_dir/tokenizer.json` without a second full copy being required by the Pyodide API. Safari cannot, according to the current FAQ. Firefox cannot either.
- In every browser, including Safari, the page can use an `<input type="file">`, read the bytes in JavaScript, and `FS.writeFile` them into MEMFS. That is a copy in the tab. The original file remains on disk. Reloading the page drops the MEMFS copy unless the page also writes it to IDBFS and calls `syncfs()`. Nothing in that sequence uploads the file unless the page’s own JavaScript posts it somewhere.
- 11 MB is small next to the runtime and next to the historical heap discussion below. No document read here sets a maximum `writeFile` size, so “11 MB is allowed” is an inference, not a stated limit.
- JupyterLite’s file browser is the same kind of in-browser copy, not a live mount of the student’s folder, based on the README’s IndexedDB/`localStorage` description. A Chrome-only `mountNativeFS` path would be custom page code around Pyodide, not the stock JupyterLite file tree.

### Gaps

- No 2026 browser-compatibility table was fetched from MDN. The Safari exclusion is the Pyodide FAQ’s current statement, plus the file-system page’s 2022-08-18 Chromium note. Those could lag a later Safari implementation.
- JupyterLite’s upload control and any upload size cap were not read; the docs site home was bot-blocked.
- It was not measured whether `mountNativeFS` reads an 11 MB file without duplicating it into the wasm heap.

## What documented limits would affect a coding lesson?

### Takeaway

The hard limits for this lesson are package format, a user gesture for local files, and the lack of a built-in time limit. Threads and subprocesses are documented as unavailable. A numeric memory cap is not stated in the current FAQ; an older maintainer comment said the wasm heap was compiled with a 2 GB maximum.

### Cited Findings

- Packages: micropip’s browser installer accepts pure-Python wheels and wasm32/Emscripten wheels only. Missing wheels abort unless `keep_going=True`, which collects the errors. Dependency resolution is on by default and can be turned off with `deps=False`. Pinned versions and extra indexes work only if the index allows CORS. Browser downloads from PyPI are cached; Node.js installs are not cached. — [micropip usage](https://micropip.pyodide.org/en/stable/project/usage.html); [micropip API](https://micropip.pyodide.org/en/latest/project/api.html)
- The built-in set for 314.0.7 is 357 packages and does not include `tokenizers` or `torch`. JupyterLite’s Pyodide kernel uses that distribution unless a custom `pyodideUrl` or extra wheels are configured. The kernel page and the wheels page disagree on whether packages can be preinstalled; see the first section. — [lockfile](https://cdn.jsdelivr.net/pyodide/v314.0.7/full/pyodide-lock.json); [wheels howto](https://jupyterlite.readthedocs.io/en/stable/howto/pyodide/wheels.html); [kernels](https://jupyterlite.readthedocs.io/en/stable/howto/configure/kernels.html)
- Network: loading Pyodide and micropip requires fetching the CDN and, for extra packages, PyPI or another CORS-enabled index. Static hosting must serve WASM with the correct MIME type and CORS. There is no documented offline mode in the pages read here. The latest CDN channel is “cached by the browser,” so a second visit can reuse the core files. — [Downloading and deploying](https://pyodide.org/en/stable/usage/downloading-and-deploying.html); [micropip API](https://micropip.pyodide.org/en/latest/project/api.html)
- Timeout: the interrupt document does not describe an automatic wall-clock limit. WebAssembly has no preemptive multitasking, so Python’s usual interrupt does not apply. Interrupts require Pyodide inside a web worker, a `SharedArrayBuffer`, and “appropriate security headers” (cross-origin isolation; the page points at MDN). The main thread writes `2` into the buffer; Pyodide raises `KeyboardInterrupt` by default. The worker must call `setInterruptBuffer`. — [Interrupting execution](https://pyodide.org/en/stable/usage/keyboard-interrupts.html)
- Threads: the current FAQ answers “Can I use threading/multiprocessing/subprocess?” with “No, fork and pthreads do not work in Pyodide.” `threading.Thread.start()` raises `RuntimeError: can't start new thread`. Calling `Thread.run()` directly still runs the target on the current thread. The sample traceback still refers to `/lib/python312.zip/threading.py`, while another example on the same FAQ prints “Welcome to Python 3.14’s help utility.” The policy sentence and the traceback path are inconsistent inside one page. — [FAQ, threading](https://pyodide.org/en/stable/usage/faq.html)
- JupyterLite’s Pyodide kernel runs in a Web Worker and “supports sleeping with `from time import sleep`.” That is a kernel behavior note, not a time limit. Multiple kernels can run at once. “Not all the features available in JupyterLab and the Classic Notebook will work.” — [README](https://github.com/jupyterlite/jupyterlite/blob/main/README.md); [Adding kernels](https://jupyterlite.readthedocs.io/en/stable/howto/configure/kernels.html)
- Memory, older statement: in issue 1513 a maintainer wrote that 4 GB is the 32-bit wasm address-space ceiling, but “the maximum memory that can be allocated in Pyodide is still 2GB, as we compile with that value of `MAXIMUM_MEMORY`,” and that raising it costs code size and was not supported by every browser. That issue is from the 2020 discussion thread, not a 2026 spec. A Stack Overflow answer repeats the 2 GB Emscripten 32-bit limit and shows a roughly 2016 MB NumPy allocation in the REPL. — [Issue 1513](https://github.com/pyodide/pyodide/issues/1513); [Stack Overflow](https://stackoverflow.com/questions/75559641/memory-limits-in-pyodide)
- The current FAQ and downloading page do not restate a 2 GB or 4 GB cap. Discussion 5458 disagrees internally about whether files count toward that heap. — [FAQ](https://pyodide.org/en/stable/usage/faq.html); [Discussion 5458](https://github.com/pyodide/pyodide/discussions/5458)
- Startup cost that is documented or measured: core files for 314.0.7 total 6,237,877 bytes across the five files listed in the first section; the full vendored tarball is “200+ megabytes.” Extra packages download when imported or installed. `torch-pyodide`’s Python wheel is 82,462 bytes and is not sufficient by itself. — [Downloading and deploying](https://pyodide.org/en/stable/usage/downloading-and-deploying.html); CDN URLs in the first section; [torch-pyodide JSON](https://pypi.org/pypi/torch-pyodide/json)
- Local files and browser support limits are in the previous section: no silent `file://` access; Chrome/Edge directory mount; not Firefox or Safari according to the FAQ; MEMFS lost on reload; native writes need `syncfs()`.

### Inferences

- A short exercise that only needs the standard library can Run inside the page after about 6.2 MB of runtime download, plus JupyterLite’s own JavaScript if the REPL iframe is used. That iframe size was not measured.
- An infinite loop on the main thread will freeze the page, because interrupts are a worker-plus-headers feature, not the default `loadPyodide()` snippet. JupyterLite already uses a worker, but still has no documented automatic timeout.
- `tokenizers` parallelism and any library that calls `Thread.start()` or `subprocess` will hit the documented thread ban even if a wheel existed.
- The 11 MB JSON is not the limiting factor under either the old 2 GB comment or the “files live outside the wasm heap” comment. The missing wheel is the blocker for `import tokenizers` and official `import torch`.

### Gaps

- No current Pyodide 314 document was found that states the compiled `MAXIMUM_MEMORY`. The 2 GB figure should stay labeled as a 2020 maintainer comment plus an undated Stack Overflow write-up.
- No official execution-timeout, CPU-quota, or per-lesson network quota was found. Browser tab crash behavior was not measured.
- JupyterLite asset download size, IndexedDB quota, and file-upload limit were not found in a fetched page.
- Whether Pyodide 314 enables pthreads when cross-origin isolation is on, despite the FAQ saying pthreads do not work, was not tested. The FAQ is the documented position, with the Python 3.12 path left as an internal inconsistency.
